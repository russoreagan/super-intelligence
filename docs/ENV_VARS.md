# Environment Variable Registry

Generated by a full sweep of the codebase on **2026-07-01**. This is the complete set of
environment variables read by Python code under `brain/` (plus a separate section for
`eval/` and `scripts/`).

**Convention: any new `BRAIN_*` variable (or any other env var the brain starts reading)
must be added to this file in the same change that introduces it.**

## How to regenerate

Sweep for the three read forms (an AST walk over the same patterns is more precise —
it catches defaults and module-level vs function-level reads):

```bash
rg -n "os\.environ\.get\(|os\.environ\[|os\.getenv\(" brain/ eval/ scripts/ --type py
# Aliased/odd forms the plain grep misses:
rg -n "environ\.get" brain/ eval/ scripts/ --type py | rg -v "os\.environ"   # e.g. `import os as _os`, `__import__("os")`
```

Also re-check `brain/run.py`'s module docstring, `.env.example`, `README.md`, and
`start.sh` for names that are documented but no longer read (see "Duplicates / suspicious").

## Legend

- **Default** — the literal fallback as coded. `(required)` = read via `os.environ[...]`
  with no fallback (raises `KeyError` when unset). `settings:<key>` = falls back to a
  `brain/settings.json` key rather than a literal.
- **Read at** — `call` = read at call time (a change is picked up live);
  `import ⚠` = read at module import time (**changing it requires a process restart**);
  `both ⚠` = read in both places (some readers see changes live, others don't).
- Locations are `file:line` at the time of the sweep.

Note: several variables are also **written** by the brain itself at boot (`brain/run.py`
exports CLI flags as `BRAIN_UI/BRAIN_DMN/...=true`, and sets `BRAIN_PERSONA_NAME`,
`SECOND_BRAIN_PATH`, `BRAIN_WIRING_PATH`, `BRAIN_WIRING_HISTORY_DIR` per persona; the
gateway sets `RUNPOD_HOST`; `brain/settings.py` and `brain/vault.py` export API keys from
settings/Vault into `os.environ`). Write sites are noted inline where relevant.
